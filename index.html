KAIROS PROPOSAL — FOR WOLF20165

端末が変わっても、
座標は裏切らない。
自動化のための専用ブラウザを、設計する。

MacroDroid・Tasker運用を前提にした、解像度固定・複数プロファイル管理対応のAndroidブラウザアプリ。 私たちKairosが、仕様書（エクセル）の一行一行を図面として読み解き、実装します。

CATEGORYAndroid App / WebView
BUDGETお見積りにて対応
DELIVERYAPK納品・約1ヶ月目安
UNDERSTANDING

これは「ブラウザアプリ」ではなく、
「自動化が信頼できる基盤」を作る仕事だと理解しています。

  • 01

    端末差による自動化の破綻
    機種ごとに解像度・表示範囲が異なり、同じマクロが別端末で動かない。これが今回の一番の根本課題だと読み取りました。

  • 02

    プロファイルの保存・切替・リセット
    単なるブックマーク機能ではなく、運用環境ごとの状態管理として設計する必要があります。

  • 03

    座標判定マーカー
    表示エリア外に基準点を置く＝マクロ側からの「アンカー」として機能させる、精密な位置合わせが要求されます。

  • 04

    Chromeの継続的バージョンアップ
    一度作って終わりではなく、年2回のメンテナンスを前提とした「運用できる成果物」が求められています。

“

「当方素人なので」とのお言葉がありましたが、ご提示いただいた要件は非常に具体的で、 自動化運用の実情を深く理解された上での仕様だと感じています。

Kairosは、エクセル仕様書を正確にトレースしながら、曖昧な部分は都度ご相談し、 長期的に「メンテできる開発体制」としてお付き合いさせていただきます。

— Kairos Development Team
WHAT WE PROVIDE

Kairosが提供できる価値

FEATURE / 01

固定解像度WebView設計

端末依存を排除し、縦横のピクセル指定どおりに表示領域を固定。どの端末でも同一の座標系でマクロが機能する基盤を構築します。

RESOLUTION LOCK
FEATURE / 02

複数プロファイル管理

保存・切替・リセットを備えたプロファイル機構を実装。Cookieやセッション状態を含め、運用環境ごとに安全に分離管理します。

PROFILE SYSTEM
FEATURE / 03

座標判定マーカー実装

表示エリア外に自動化用の基準マークを設置。MacroDroid/Taskerからの座標検出が安定して行える構造を設計します。

ANCHOR POINT
FEATURE / 04

画像非表示モード

通信量削減・表示速度向上のため、画像を非表示にしてもレイアウトが崩れないCSS制御を実装。自動化精度を落としません。

LIGHTWEIGHT MODE
FEATURE / 05

継続的なメンテナンス体制

年2回程度のChromeエンジン更新、不具合対応、仕様追加まで、長期サポート前提で継続的にお付き合いします。

LONG-TERM SUPPORT
PROCESS

進め方・スケジュールイメージ

STEP01

仕様確認・要件すり合わせ

添付エクセルの仕様を精査し、プロファイル項目・表示範囲・マーカー位置など不明点をヒアリングしながら要件を確定します。

約3〜5日
STEP02

画面・構造設計

プロファイル管理の画面構成、解像度固定の実装方式、座標マーカーの配置ロジックを設計し、開発前に認識合わせを行います。

約3〜4日
STEP03

実装・内部テスト

WebView実装、プロファイル機能、表示範囲固定、画像非表示モードなどを順次実装し、複数端末での動作確認を行います。

約2〜3週間
STEP04

実機確認・微調整

実際の自動化運用を想定したテストを行い、座標ズレやレイアウト崩れがないかを確認。必要に応じて微調整します。

約3〜5日
STEP05

APK納品・運用開始

APK形式で納品。以降、Chromeバージョンアップ（年2回程度）や、自動化（マクロ）開発のご相談にも継続対応いたします。

納期目安：1ヶ月以内
